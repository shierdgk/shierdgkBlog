## 前言

蒜泥科技实习后期接触了一些性能测试。公司老项目用 LoadRunner，我自己学 JMeter。聊聊入门心得：别被工具吓倒，核心思路就一句——模拟真实用户行为，观察系统反应。

## 一、先搞清楚测什么

新手最容易一上来就狂压，报告一堆数字自己都看不懂。动手前先问三个问题：

- 目标是什么？是看最大并发，还是看稳定性，还是找瓶颈？
- 真实用户怎么用？哪个接口是热点？
- 通过标准是什么？响应时间、错误率红线在哪？

## 二、LoadRunner vs JMeter

LoadRunner 功能强但重，License 贵、脚本用 C 写，门槛高。JMeter 开源、Java 写、社区大，GUI 就能搭脚本：

~~~
Thread Group
  └─ HTTP Request (登录)
  └─ HTTP Request (查询列表)
  └─ View Results Tree / Aggregate Report
~~~

我实习时先用 LoadRunner 跑老脚本，自己用 JMeter 搭新场景，对比着学，理解更快。

## 三、别只盯 TPS，要看瓶颈在哪

压测报告 TPS 上去了，但响应时间也涨，说明到瓶颈了。我用 JMeter + 服务器监控（CPU、内存、慢 SQL）定位：发现是某个没加索引的查询拖垮整体，加完索引 TPS 翻倍。

> 性能测试不是「把机器跑死」，是「找到那根最短的木板」。没有监控的压测只是表演。

## 小结

工具只是手段。想清楚目标、设计好场景、配好监控，LoadRunner 还是 JMeter 没那么重要。新手从 JMeter 入门性价比最高。
